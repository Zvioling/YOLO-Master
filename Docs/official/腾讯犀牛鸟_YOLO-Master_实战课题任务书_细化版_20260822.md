# 1. 仓库事实与共同技术边界

仓库定位是面向实时目标检测的 YOLO-style 框架，核心是 ES-MoE
与动态路由；当前主页同时列出 MoA、MoT、LoRA/YOLO-PEFT、Agent
Skill、诊断剪枝、Sparse SAHI、CW-NMS 与部署能力。

不要把 README
中已有的功能写成“从零开发”。课题应明确属于：补齐闭环、修复缺口、严谨复测、扩展任务、工具化或产品化。

所有代码位置引用必须在锁定 commit
后重新搜索与验证；不要沿用旧文档中的绝对行号。

新增辅助损失或路由类型时，必须验证训练总损失实际收到该项，并用单测或非零日志证明；不能只看配置键存在。

动态路由导出必须显式处理不支持、拒绝或 sparse→dense
fallback；不允许静默改变模型语义。

WebUI 统一复用 Agent Skill/dispatcher 执行，不直接拼接任意 shell。

## F11 教师软目标的最低合法定义

不能直接把 DINO patch 特征当作专家编号；两者语义空间不同。

建议以“各专家输出与教师特征的一致性”或“各专家对当前样本/token
的效用”形成 q_teacher，并记录温度、平滑和置信度掩码。

必须证明 q_teacher 不是恒定均匀分布或单专家坍塌，并对比无 KD、表征 KD 和
Router KD。

训练期可计算全部专家形成教师目标；推理期必须恢复学生稀疏路由，不保留教师模型。
