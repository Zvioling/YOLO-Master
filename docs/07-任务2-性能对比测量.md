### 2.0 任务原文（Issue #54 原文）

> 对比测量每种变体的：mAP50-95、mAP50、Latency（ms，P50/P95/P99）、FLOPs（实际）、Params（M）、训练稳定性（loss 曲线是否发散、是否出现 NaN）

### 2.1 任务介绍

本任务对 3 个模型变体（MoE 基线、MoT 变体、MoA 变体）进行全面的性能评估。需要测量 6 项指标：

| 指标 | 含义 | 工具 |
|------|------|------|
| mAP50-95 | IoU 0.5-0.95 的平均精度 | 训练时自动记录 |
| mAP50 | IoU 0.5 的平均精度 | 训练时自动记录 |
| Latency | 推理延迟（CPU/GPU） | `compare_mot_ablation.py --benchmark` |
| FLOPs | 浮点运算量 | `model.info()` |
| Params | 参数量 | `model.info()` |
| 训练稳定性 | loss 收敛情况、NaN 检测 | `results.csv` |

**评估目标**：量化 MoT 相比 MoE 基线的精度与效率增益。

### 2.2 实验步骤（命令行 + 终端输出 + 汇总说明）

### 步骤 1：延迟测试（Latency）

**目标**：测量各变体在 CPU 和 GPU 上的推理延迟

**命令行（CPU 延迟）**：
```powershell
python scripts/compare_mot_ablation.py --benchmark --imgsz 640 --warmup 100 --reps 1000 --device cpu
```

**命令行（GPU 延迟，仅在有 NVIDIA GPU 时可用）**：
```powershell
python scripts/compare_mot_ablation.py --benchmark --imgsz 640 --warmup 100 --reps 1000 --device cuda:0
```

**说明**：
- `--benchmark` 模式不需要 `--data`（仅 `--train` 模式需要数据集）
- `--models` 默认为 `v08 v08_moa v08_mot v08_moa_mot`，会一次跑 4 个变体
- `--device` 必须传完整 device 字符串（`cpu` / `cuda:0` / `mps`），**不能传 `0`**（`torch.device(0)` 会报错）
- **Windows 文件名兼容性**：脚本 `f"latency_{device}_{imgsz}.csv"` 中 `cuda:0` 含 `:`，Windows 不允许文件名含 `:`，会导致写入失败。已在脚本中修复：`device_safe = args.device.replace(":", "_")`，输出文件名变为 `latency_cuda_0_640.csv`
- GPU 命令输出文件（修复后）：`runs/mot_ablation/latency_cuda_0_640.csv`

### 步骤 5：mAP 汇总

**目标**：汇总各变体的 mAP50-95、mAP50、Precision、Recall

**前提条件**：
- `runs/mot_ablation/v084/results.csv`、`v08_mot6/results.csv`、`v08_moa2/results.csv` 三个文件存在
- 因 spec key 与目录名不匹配，**直接运行 `--summary-only` 无法读取数据**，需要先做一次目录链接或复制

**方法 A：建立符号链接（需管理员权限或开发者模式，且必须在项目根目录的 PowerShell 中执行）**

> ⚠️ **实测警告**：在非管理员 PowerShell 中执行会报 `Administrator privilege required for this operation.`，且 `--summary-only` 会跳过缺失目录，导致 summary.csv 为空。
>
> 解决方法：① 用管理员权限打开 PowerShell；② 开启 Windows 开发者模式（设置 → 更新和安全 → 开发者选项 → 开发人员模式）；③ 直接改用方法 B。

```powershell
# 在 runs/mot_ablation/ 下建立 spec.key 到实际目录的符号链接
New-Item -ItemType SymbolicLink -Path runs\mot_ablation\v08 -Target runs\mot_ablation\v084
New-Item -ItemType SymbolicLink -Path runs\mot_ablation\v08_moa -Target runs\mot_ablation\v08_moa2
New-Item -ItemType SymbolicLink -Path runs\mot_ablation\v08_mot -Target runs\mot_ablation\v08_mot6

# 然后运行 summary-only（必须加 --project runs\mot_ablation，否则会用默认路径）

```

**方法 B（推荐）：复制 results.csv 到 spec.key 目录**——无需任何特殊权限


### 2.5 关键发现与洞察

**1. 精度与效率的权衡**
- MoT 变体 mAP50-95 仅高 0.09%，但计算量增加 58%、参数增加 18%
- 边际精度收益不足以支撑显著的效率成本
- **建议**：将 MoT 应用于 GPU 服务端场景，而非边缘设备

**2. MoA vs MoT 的差异化**
- **MoA**：Precision 最高（0.40745），attention 聚焦正样本，但 Recall 最低
- **MoT**：Recall 最高（0.31222），窗口/可变形注意力捕获更多正样本
- 两者形成互补，**MoA+MoT 混合架构可能成为未来探索方向**

**3. GPU 加速比的差异化**
- MoT 在 GPU 上加速比最高（3.11×，172.660/55.441），说明其 attention 机制在 GPU 上可并行
- MoA+MoT 混合变体 GPU Max 延迟波动大（563.92ms vs Mean 68.69ms），存在 GPU kernel 调度不稳
- 已采用标准 benchmark（warmup=500, reps=2000）重测 MoT 系列变体，结果稳定；v08/v08_moa/v08_moa_mot 因 7 月测量条件略低（warmup=100, reps=1000）未重测

**4. 训练稳定性**
- 所有变体 loss 曲线平滑收敛，无 NaN
- `train/moe_loss` 从 0.33 降至 0.0，路由机制稳定
- MoT 训练时间比 MoE 长 47%，但仍在 RTX 5060 8GB 可承受范围

**5. 工程实现发现**
- `compare_mot_ablation.py` 的 CSV 文件名拼接存在 Windows 兼容 bug（`cuda:0` 含 `:`）
- 已在脚本中修复：`device_safe = args.device.replace(":", "_")`
- 该修复是 Issue #54 任务 6 的"附带 PR 贡献"
