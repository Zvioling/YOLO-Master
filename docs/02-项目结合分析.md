## 3. 项目一与我项目的具体结合点

### 3.1 技术延伸路径

```
Issue #54 已完成 → 项目一 ES-MoE
├── v08_moe（MoE 基线）    → ES_MOE（深度可分离路由 + 多尺度专家）
├── v08_mot（MoT 变体）    → 路由可视化 + 热力图（直接套用）
├── 方案 D（SharedExpert） → ES-MoE Soft-to-Hard 切换 + Top-K 对比
├── Benchmark 体系        → 标准化延迟测量（warmup=500/reps=2000）
└── ES-MoE 训练（已有）   → esmoe_v0_k2-2（100 epoch，13h，mAP=17.27%）
```

### 3.2 三个项目的关系（叙事完整性）

| Issue #54 项目 | 在 Issue #54 体系中的位置 | 项目一 ES-MoE 的位置 |
|---------------|--------------------------|---------------------|
| v08_moe | MoE 基线（静态专家） | ES_MOE 是其**路由增强版** |
| v08_mot | MoT 变体（3 专家 Top-K） | 路由分析框架可复用 |
| 方案 D | 跨尺度共享（参数削减） | ES-MoE 是**精度-效率平衡**路线 |

### 3.3 项目一相比项目二/三的独特优势

| 优势 | 详细说明 |
|------|---------|
| **能力延伸性最强** | ES-MoE 是 MoE 路由变体，与 Issue #54 已掌握的 MoT 路由机制**完全同源** |
| **仓库原生支持** | `ES_MOE` 模块 + `yolo-master-esmoe-n-visdrone.yaml` 现成，无需额外集成 |
| **训练数据复用** | VisDrone 已熟悉 + `esmoe_v0_k2-2` 100 epoch 完整数据已存（**节省 13h 重训**） |
| **验证体系一致** | 沿用 warmup=500/reps=2000 标准，对比 Issue #54 数据更规范 |
| **风险最低** | 无第三方依赖（LoRA 需 peft）、无环境门槛（剪枝需 TensorRT/ncnn） |
